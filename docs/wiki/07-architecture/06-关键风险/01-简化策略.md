### 简化策略

1. **Agent 执行优先做"半自动"**：编码 → PR → 人工 Review → 合并，而非全自动合入 main
2. **讨论先做"指令触发"**：Agent 不实时监听所有消息，通过 `/backlog` 触发，避免 Token 浪费
3. **Skills 系统复用现有模式**：项目已有 `flowcode_design/executor/todo/wiki` Skill 定义，直接复用 YAML frontmatter + Markdown body 的格式

4. **可观测性三件套（Phase 1 必须具备）**：
   - **Trace ID**：从 Hub → Orchestrator → Worker → Sandbox 全链路串联，每个请求生成唯一 `trace_id`，写入所有日志和 agent_logs
   - **Health Check**：`/health/live`（进程存活）+ `/health/ready`（依赖就绪：MySQL/Redis/Docker 连通性）
   - **Metrics**：Prometheus 格式暴露核心指标（队列长度、执行时间 P50/P99、Token 用量、活跃容器数）

5. **熔断器（Circuit Breaker）**：
   - LLM API 调用：3 次超时后熔断 30s，期间新请求排队等待
   - Docker API 调用：超时 60s 后熔断，Worker 自杀重启
   - GitHub API 调用：422/429 响应后指数退避重试（最多 3 次）

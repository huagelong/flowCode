## 注意事项

1. **Redis 必须开 AOF** — 否则服务器重启后 Asynq 任务队列丢失，`in_progress` Issue 无法恢复
2. **Docker 容器 AutoRemove=false** — 配合 `RecoverRunningIssues` 恢复机制
3. **端口 8080** — 唯一对外端口（API + WebSocket + 两个 SPA 全在同一个端口）
4. **单二进制部署** — `admin/dist` 和 `client/dist` 通过 Go embed 打入，服务器不需要 Node.js 运行时
5. **沙箱镜像仅含 anserflow 二进制** — `anserflow agent run`（Go 二进制）+ git + bash，`ENTRYPOINT ["/entrypoint.sh"]` 由 Go Docker SDK 调用

### Redis 高可用与容灾

| 部署模式 | Redis 方案 | 适用场景 |
|---------|-----------|---------|
| 单机一体化 | Redis Sentinel（1主2从+3哨兵） | 推荐起步 |
| 分布式 | Redis Cluster（3主3从） | 多实例 Worker |

**Sentinel 配置要点**：
- `redis.conf`: `appendonly yes` + `appendfsync everysec`（保障 Asynq 任务持久化）
- Sentinel `down-after-milliseconds`: 5000ms
- Sentinel `failover-timeout`: 10000ms
- Go 客户端使用 `github.com/redis/go-redis/v9` 的 Sentinel 模式

**Redis 不可用时的降级策略**：
| 功能 | Redis 不可用时的行为 |
|------|-------------------|
| WebSocket | 降级为单实例模式（同节点的客户端仍可通信，跨节点消息丢失） |
| 任务队列 | Asynq 无法入队，新任务排队失败，API 返回 503 |
| Token 追踪 | 本次执行 Token 不计入配额，Redis 恢复后异步补录 |
| 记忆写入锁 | 降级为进程内 Mutex（单实例安全，多实例可能冲突） |

> Redis Sentinel 至少需要 3 个哨兵进程才能安全选举。单机部署时可以和 API Server 共存。
